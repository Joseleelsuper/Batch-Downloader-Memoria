\apendice{Anexo de sostenibilización curricular}

\section{Introducción}

Las directrices de la CRUE entienden la sostenibilidad como la búsqueda conjunta de calidad ambiental, justicia social y una economía viable y equitativa, y proponen cuatro competencias transversales: contextualización crítica, uso sostenible de recursos, participación y aplicación de principios éticos~\cite{crue2012}. La implementación de Batch Downloader permite contrastar estas dimensiones con mecanismos concretos y obliga a considerar consecuencias que no aparecen si el proyecto se analiza solo como un problema técnico.

\section{SOS1: contextualización crítica}

La utilidad de la plataforma nace de una práctica extendida: al preparar un ordenador, cada usuario repite búsquedas y descargas en múltiples páginas. Centralizar el catálogo puede ahorrar tiempo y reducir el acceso accidental a sitios no oficiales. Sin embargo, esa comodidad también concentra responsabilidad. El servicio procesa ejecutables de terceros, depende de proveedores globales y puede generar un consumo elevado de red, disco y energía si se usa de forma indiscriminada.

El análisis relaciona, por tanto, la experiencia individual con efectos más amplios. Una descarga fallida no es solo un error de programación: puede deberse a restricciones regionales, condiciones de uso, accesibilidad insuficiente o cambios comerciales del proveedor. La búsqueda semántica se limita al catálogo controlado y conserva filtros explícitos y fallback literal. Aun así, sus benchmarks deberán vigilar sesgos que favorezcan aplicaciones populares y oculten alternativas pequeñas o libres. No se implementan recomendaciones generativas.

\section{SOS2: uso sostenible de recursos}

El principio técnico más directamente relacionado con la sostenibilidad es no almacenar instaladores de forma permanente. Mantener copias de cada versión multiplicaría el uso de almacenamiento y obligaría a gestionar duplicados obsoletos. Batch Downloader descarga los archivos únicamente durante el trabajo, genera el ZIP y elimina staging y temporales al finalizar, cancelar o expirar.

Esta decisión no elimina el impacto. Agrupar aplicaciones puede aumentar la transferencia si el usuario selecciona programas que después no necesita. La interfaz muestra contenido y resultados omitidos antes y después de confirmar. Se aplican límites de 100 aplicaciones, 4 GiB por archivo, 20 GiB por trabajo y ocho descargas concurrentes. Una fuente validada permanece seleccionable hasta una invalidación explícita y, cuando su resolución caduca, se revalida justo antes de descargar para evitar trabajo preventivo innecesario.

La inteligencia artificial merece una atención específica. Los embeddings se generan localmente a partir de un hash de contenido, de modo que no se recalculan documentos sin cambios. Las llamadas a Groq o DeepSeek se limitan al enriquecimiento asíncrono de descripciones ausentes y rotan de modelo cuando se agota una cuota. La clasificación del catálogo y el fallback literal siguen funcionando sin ningún modelo. El benchmark registra RAM, VRAM, latencia y tamaño de índice, aunque una medición energética completa queda fuera de esta entrega.

\section{SOS3: participación}

Las solicitudes de software permiten que los usuarios propongan incorporaciones, mientras que los bundles públicos u oficiales ofrecen colecciones reutilizables mantenidas por administración. Solo los administradores aprueban aplicaciones, fuentes y bundles. Las estrellas, la clonación y la personalización comunitaria no forman parte de la entrega y se tratan como ampliaciones posibles, no como mecanismos ya disponibles.

La participación también implica escuchar problemas de accesibilidad y uso. El proyecto ofrece navegación por teclado, estados ARIA para los filtros y mensajes comprensibles de progreso. Los registros técnicos no bastan para conocer la experiencia: las pruebas con usuarios y la revisión de solicitudes deben influir en la priorización.

\section{SOS4: principios éticos}

La plataforma actúa con transparencia. Antes de descargar se explica que los archivos proceden de fuentes oficiales, se procesan temporalmente y no se ejecutan. El manifiesto identifica aplicaciones y fuentes, y los errores no se ocultan detrás de mensajes genéricos.

La privacidad se aplica mediante minimización de datos, plazos de conservación y protección de cuentas, direcciones IP, registros y correos. Los trabajos anónimos almacenan únicamente el HMAC de una cookie aleatoria. Los logs y el contexto enviado al LLM excluyen secretos y datos innecesarios. Los textos y consultas de embeddings permanecen en la infraestructura local. El LLM solo redacta descripciones: no aprueba enlaces, no clasifica aplicaciones ni realiza acciones administrativas.

También existe una responsabilidad económica y social. La funcionalidad básica para usuarios anónimos evita convertir el acceso en una obligación de registro. Si se despliega públicamente, las cuotas deben proteger la infraestructura sin discriminar a quienes tengan conexiones lentas. El proyecto respeta las licencias y condiciones de los editores, no presenta software de terceros como propio y ofrece información suficiente para que el usuario tome una decisión.

\section{Conclusión personal}

La sostenibilidad no se reduce a declarar una intención. En esta entrega se puede comprobar que no se almacenan instaladores de forma permanente, que los objetos temporales tienen retención limitada, que las descargas están acotadas, que los embeddings se actualizan por hash y que el LLM se limita a texto descriptivo fuera de las acciones críticas. Falta medir el consumo energético y la transferencia en una campaña de carga; hasta entonces, no se atribuye al proyecto una mejora cuantificada de impacto ambiental.

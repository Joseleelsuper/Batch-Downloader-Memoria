\capitulo{1}{Introducción}

\section{Contexto y problema}

La preparación de un ordenador nuevo, la reinstalación del sistema operativo o la configuración de un puesto de trabajo suelen exigir la descarga de numerosas aplicaciones. Aunque cada fabricante publica sus instaladores en páginas oficiales, el usuario debe localizar dichas páginas, identificar la versión adecuada para su sistema y repetir el proceso para cada programa. Esta tarea es mecánica, consume tiempo y aumenta la posibilidad de utilizar enlaces obsoletos o sitios no oficiales.

\emph{Batch Downloader} es una plataforma web que centraliza el descubrimiento y la descarga de software sin convertirse en un repositorio permanente de ejecutables. El catálogo mantiene información descriptiva, metadatos y referencias cifradas a instaladores; los binarios se vuelven a validar y se obtienen cuando el usuario solicita una descarga. El worker reúne temporalmente los archivos aceptados, construye un ZIP con su manifiesto y elimina los artefactos al expirar el resultado.

El proyecto comparte con servicios como Ninite la idea de reducir las acciones necesarias para preparar un equipo. Ninite permite seleccionar varias aplicaciones y generar un instalador personalizado, descarga cada programa desde el sitio de su editor y verifica firmas o resúmenes antes de ejecutarlo~\cite{ninite}. Batch Downloader se diferencia por ofrecer un catálogo administrable y observable, filtros por plataforma, bundles mantenidos por la administración, generación de ZIP en servidor y un pipeline desacoplado que conserva el historial de resolución.

\section{Motivación}

La motivación principal es simplificar un proceso frecuente sin renunciar a la trazabilidad. El usuario debe conocer qué aplicaciones ha elegido, desde qué dominio se obtiene cada instalador y por qué un archivo no ha podido incluirse. Esta transparencia es especialmente importante porque la plataforma procesará ejecutables de terceros y dependerá de páginas externas que pueden cambiar sin previo aviso.

El sistema también aborda un problema de organización. Una selección habitual, como un entorno de desarrollo, un conjunto de utilidades multimedia o las aplicaciones básicas para un equipo nuevo, puede expresarse como un \emph{bundle}. La implementación permite consultar y descargar colecciones oficiales y públicas, mantiene las oficiales desde el panel administrativo y permite a cada cuenta gestionar sus propios bundles públicos o privados desde el panel personal. Las funciones de clonación, personalización de bundles ajenos y valoración no forman parte de la entrega.

El buscador ofrece un modo literal y otro semántico. El primero combina coincidencias normalizadas de nombre, editor y descripción; el segundo consulta la proyección de embeddings locales y entrega candidatos que Core vuelve a filtrar y paginar con MySQL. MySQL conserva la autoridad sobre estados, filtros, facetas, totales y paginación. PostgreSQL con pgvector mantiene una proyección reconstruible y el sistema degrada la petición completa al modo literal cuando el modelo o el índice no están disponibles, la consulta no es elegible o la enumeración no puede completarse.

El modelo de embeddings se aprovisiona localmente y el servicio arranca en modo sin red para pesos; las descripciones, los metadatos y las consultas no se envían a un proveedor de inferencia.

\section{Alcance de esta memoria}

Esta memoria documenta una iteración implementada de Batch Downloader. El repositorio contiene el catálogo web, los servicios Java, el scraper Python, los contratos de mensajería y los flujos de descarga asíncrona. La versión actual está desplegada en un VPS de Oracle mediante Coolify; esto acredita el procedimiento operativo y los smoke tests externos, pero no una campaña de carga sostenida.

El alcance funcional incluye:

\begin{itemize}
	\item consulta y filtrado de un catálogo de aplicaciones.
	\item selección individual o múltiple y generación de un ZIP en servidor.
	\item sesiones para usuarios anónimos, registrados y administradores.
	\item consulta y descarga de bundles oficiales y propios públicos o privados; cada cuenta dispone de un panel personal para gestionarlos.
	\item historial de descargas, verificación de correo y recuperación de cuenta mediante restablecimiento de contraseña.
	\item resolución periódica de fuentes, revalidación inmediata y revisión administrativa.
	\item clasificación persistente en disponible, revisión y sin instalador, con contadores incrementales.
	\item búsqueda literal y semántica con selector persistente, degradación íntegra y versiones explícitas de modelo e índice.
	\item selección de versión y perfil de instalador, descubrimiento e inspección manual, accesos \ruta{.url} y estados \emph{PACKAGING} y \emph{MANUAL\_ONLY}.
	\item bundles Linux con perfiles APT, DNF, Pacman y Zypper, comprobaciones SHA-256/GPG y rollback.
	\item observabilidad de trabajos, colas, reintentos y cambios del catálogo.
\end{itemize}


La entrega no declara una medición de capacidad en producción. Sí incorpora manuales de programación y de usuario contrastados con el repositorio, los contratos OpenAPI y AsyncAPI, pruebas automatizadas para los cuatro servicios Java, el scraper y el frontend, y una verificación de los smoke tests publicados. Las baterías no ejecutadas en el commit de corte se marcan como no verificadas.
